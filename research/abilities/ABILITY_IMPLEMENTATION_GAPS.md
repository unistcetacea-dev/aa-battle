# 특성 구현 상태와 보류 기준

특성은 포텐셜 슬롯이나 포텐셜 이름으로 저장하지 않는다. 포켓몬의 `ability` 이름이 특성 도감의 독립 정의를 참조하며, 원문은 `ability-catalog.gz.b64`에 보존한다. 트리거·효과의 문장 분리는 공용 `RuleText`를 사용하지만, 특성의 발동과 포텐셜의 발동 기록은 서로 섞지 않는다.

## 현재 자동 연결

- 기존 전투 규칙으로 검증된 면역·흡수·상태이상 방지·날씨 보정·기술 보정 특성은 `Mechanics.KnownAbilities`에 한정해 자동 처리한다.
- 등장 특성 `가뭄`, `잔비`, `모래날림`, `눈퍼뜨리기`, `그래스메이커`, `일렉트릭메이커`, `사이코메이커`, `미스트메이커`는 최초 등장과 교대 등장 시 5T 날씨/필드를 전개한다.
- 특성 발동은 공용 확정 트리거 사건(`AnsweredTriggers`)에 전달하되, 포텐셜 그 자체로 저장하거나 실행하지 않는다.
- 랭크 변화 특성 `심술꾸러기·단순·클리어바디·하얀연기·미러아머·오기·승기`, 기술 보정 `적응력·테크니션·철주먹·메가런처·옹골찬턱·예리함·이판사판`, 퇴장 특성 `재생력·자연회복`, 턴 종료 특성 `가속`, 방호 특성 `멀티스케일·옹골참`, 무효화 특성 `화학변화가스`를 전용 런타임에서 처리한다.

## 사용자 확정 규칙 (2026-09-16)

- 전투 중 특성을 새로 얻어도 등장 특성은 즉시 발동하지 않는다. 다시 등장해야 한다.
- 특성 무효화가 끝나면 상시 특성만 즉시 재개한다. 등장 특성은 재등장 전까지 발동하지 않는다.
- `틀깨기` 계열은 상대 특성을 없애지 않고 해당 기술 판정의 방어 특성만 무시한다.
- 같은 시점 특성 처리는 속도순이다.
- 특성의 위력·능력·최종 대미지 배율은 포텐셜과 같은 계산 단계를 사용한다.
- HP 조건 방호는 연속기의 각 타격마다 다시 판정한다.
- 피격 교대 특성은 연속기를 모두 받은 뒤 교대한다.
- `재생력·자연회복`은 임의교대·강제교대·유턴·『돌아와！』에 적용하고 빈사 퇴장에는 적용하지 않는다.
- 폼 변경으로 최대 HP가 달라질 때 현재 HP 비율을 유지한다.
- 다인전 전용 특성은 수동으로 유지한다.
- 『돌아와！』는 기존 포켓몬이 먼저 볼로 들어가 상대의 대상 지정 행동을 피한 뒤 턴 마지막 교대 시점에 새 포켓몬이 등장한다.

## 수동 사유 분류

특성 도감은 각 특성을 `자동` 또는 `수동`으로 표시하고, 수동 특성에는 아래 사유를 붙인다. 도감 검색은 이름·원문·분리된 트리거·효과·사유까지 포함한다.

| 사유 | 아직 필요한 하위 시스템 |
| --- | --- |
| 다인전 대상/범위 엔진 필요 | 인접, 아군 전체, 다수 대상의 선택·순서·대상 규칙 |
| PP·기술 이력/교체 엔진 필요 | PP, 마지막 사용 기술, 봉인·복사·교체 |
| 폼·종족 데이터 변경 엔진 필요 | 폼체인지, 변신, 종족치·타입의 지속/복원 |
| 특성 교체·무효화 상태 엔진 필요 | 특성 상실·교환·복사·무효화와 틀깨기 우선순위 |
| 선택/난수 규칙 확정 필요 | 임의 능력치·무작위 대상·확률 선택의 UI/난수 규칙 |
| 교대·파티 선택 엔진 필요 | 강제/임의 교대, 파티 대상, 교대 불가·추적 |
| 효과 실행기 미구현 | 위 범주에는 들지 않지만 전용 상태·기술·필드 규칙이 아직 없는 효과 |

수동 표기는 미구현을 숨기지 않기 위한 상태다. 효과 원문을 자동 실행 가능한 규칙으로 추정하지 않으며, 개별 특성은 필요한 하위 시스템이 추가된 후에만 `자동`으로 승격한다.
