# 포텐셜 트리거 규칙 질문 50개

작성: 2026-09-15. 확인 기준: 로컬/GitHub fb32acc.

수집한 포텐셜 4,151개와 EntryTriggers.cs, TriggerBatchTests.cs, PotentialProbability.cs를 비교해 추린 구현 과제다. 같은 구조의 타입·기술·이름 차이는 한 항목으로 묶었다. 아래 문구는 구조를 설명하기 위한 축약 예시이며 원문 그대로의 인용 목록은 아니다.

‘미지원’은 구현 불가능하다는 뜻이 아니다. 전용 조건 판정이나 이벤트 연결이 아직 없거나, 일부만 있어 적용 범위를 정해야 한다는 뜻이다. 기존 트리거도 대부분 조건 충족 로그와 실제 효과 실행이 분리되어 있다. 현재 코드 동작을 작품의 확정 규칙으로 간주하지 않는다.

답변은 `01: ...` 형식으로 주면 된다. 지금 넣지 않을 것은 `보류`, 이전에 정한 것은 `기존 규칙 유지`로 답해도 된다. 답변을 받은 뒤 각 번호를 구현·검증 가능한 작업으로 확정한다. 아직 게임 파일은 수정하지 않는다.

## 확인 범위와 다음 완료 조건

- 기본 등장·상대 등장·직접 공격 처치·턴 종료·일반 기술 사용·일반 공격 성공·일반 피해·지령 수령·첫 해석 등의 기존 경로를 처음부터 다시 정의하는 목록은 아니다. 그 위에 붙는 조건이나 연결되지 않은 이벤트를 추렸다.
- 이미 코드에 정해진 「여기다」의 생존 수 기준, 확률 10/20/50%, 중확률 실패 보정은 이번 질문에서 제외했다.
- 일반 등장에서 강제교대를 제외하는 현행 규칙을 바꾸자는 요청이 아니다. 46번은 원문에 강제교대가 명시된 별도 조건이다.
- `TRIGGERS.md`에는 강제 등장도 포함한다고 적혀 있지만 실제 `EntryTriggers.IsEntry`와 테스트는 제외한다. 구현 시 문서를 코드 및 사용자 답변과 맞춰야 한다.
- 47번은 `TryStatusCondition`의 입력·정규화 지원과 실제 배틀 사건 판정을 구별한 항목이다.
- 대표 원문 근거는 `potential-catalog.json`의 `triggers`와 `raw`. 예: 구르메 세포(나무열매 소모), 마목차의 교란/통찰(역할 발동), 강습함의 함정(특성 발동). 추출된 `이때`, `1/시/T시/1T동안` 등을 독립된 정상 트리거로 세지 않았다.
- 각 번호는 답변 확정 → 구조 데이터 정의 → 조건 성립/불성립 검사 → 관련 사건 연결 → 중복 발동·교대·빈사 경계 검사 순으로 완료한다. 일반 효과 실행 엔진까지 완성됐다는 의미로 표시하지 않는다.
