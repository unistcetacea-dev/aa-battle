# 포텐셜 실행 모델 초안

포텐셜의 이름이나 분류만으로 동작을 결정하지 않는다. 한 포텐셜을 다음 요소로 나눠야 한다.

1. **소유자와 범위**: 자신, 상대, 아군, PT 전체, 트레이너, 필드.
2. **발동 방식**: 상시, 자동, 임의, 선행 선언.
3. **사용 제한**: 1/시, 1/선발, 턴당 횟수와 중복 발동 제한.
4. **트리거**: 배틀 시작, 등장, 퇴장, 기술 선택, 행동 전, 명중, 피격, 대미지 후, 빈사, 턴 종료 등.
5. **조건**: 타입, 기술 분류, 우선도, HP, 날씨, 필드, 역할, 상대 상태처럼 트리거 시 검사할 값.
6. **효과**: 능력 변화, 배율, 무효화, 타입/기술 속성 변경, 회복·대미지, 교대, 추가행동, 상태·필드 생성 등.
7. **제약과 예외**: 빈사 불가, 방호 관통 여부, 대타 대상 여부, 강제교대 면역처럼 효과 실행을 제한하는 문장.

예를 들어 `필드를 떠날 때, 자진을 2T간 순풍 상태로 한다`는 `field_exit` 트리거와 `weather_terrain` 효과로 나뉜다. 효과 값에는 지속시간 2T를 저장한다. `1/시/선행`은 트리거 문장이 아니라 사용 제한과 발동 방식이다.

## 카테고리와 동작의 관계

역할·분류·주인·이명·종족·속별·유대·선·대○·범용·부수·특권·PT·전용·고유는 포텐셜의 슬롯 또는 출처 분류다. 같은 분류 안에도 트리거와 효과가 전혀 다른 규칙이 있으므로 실행기에서는 별도 필드로 둔다. 포텐셜 일람은 이 분류 체계와 표준 포텐셜의 기준 사전으로 사용한다.

## 나중에 필요한 이벤트 순서

실제 엔진에 넣을 때는 최소한 `배틀 시작 → 등장 → 기술 결정 → 우선도/행동순서 결정 → 행동 직전 → 기술 처리 → 명중/피격 → 대미지 후 → 빈사 판정 → 교대 → 턴 종료` 순서의 이벤트가 필요하다. 각 단계에는 포텐셜이 다시 포텐셜을 발동시키는 경우를 막는 중복 제한과, 여러 효과의 처리 순서를 정하는 큐가 필요하다.

`potential-catalog.json`의 자동 태그는 이 실행 모델로 옮기기 위한 색인이다. 원문이 최종 기준이며, `review` 항목은 사람이 조건과 효과를 확정하기 전까지 실행 가능한 규칙으로 사용하지 않는다.
