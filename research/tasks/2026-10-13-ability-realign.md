# 지시서: 전용 코드 특성 63개를 도감 문장 기준으로 다시 맞추기

작성: Claude (2026-10-13) · 구현: ChatGPT(Codex) · 기준 커밋: `1240591`

먼저 `AGENTS.md`, `PROJECT_HANDOFF.md`의 「2026-10-13 특성 모듈 1단계」, `research/abilities/ABILITY_IMPLEMENTATION_GAPS.md`를 읽는다.

## 목표
지금 전용 코드로 처리하는 특성 63개(`AbilityModules.Dedicated` = `Mechanics.KnownAbilities` + `AbilityRuntime.EntryAbilities` + `AbilityRuntime.SupportedAbilities`)를 특성 도감 문장 기준으로 다시 맞춘다.
- 도감 문장을 기존 모듈로 다 표현할 수 있으면: 전용 코드를 지우고 모듈(`AbilityModules` 슬롯 「특성」)로 옮긴다.
- 일부만 표현할 수 있으면: 표현되는 문장만 모듈로 돌리고, 나머지만 전용 코드로 남긴다(아래 「부분 모듈」).
- 도감과 지금 동작이 다른 수치·범위는 도감 문장에 맞춘다.

## 사용자 결정(바꾸지 말 것)
- 기준 우선순위: 특성 도감 문장 → 오레마스 문서(`doku.php?id=<문서명>&do=export_raw`) → 실기(Showdown).
- 특성은 포텐셜과 같은 실행기로 돌리되 슬롯 「특성」, 로그 〔특성명〕은 분리하고 포켓몬 데이터에 저장하지 않는다.
- 모듈로 표현할 수 없으면 새 모듈(표준 문장 + 실행기/판정 지점 + `EffectModules.Normalize/Classify` 연결)을 만든다. 특성 이름별 `if` 분기를 새로 만들지 않는다.
- 2026-09-16 확정 규칙(`ABILITY_IMPLEMENTATION_GAPS.md`)은 유지: 전투 중 얻은 특성의 등장 효과는 재등장 전까지 발동하지 않음, 무효화가 끝나면 상시 효과만 재개, 틀깨기는 해당 기술 판정의 방어 특성만 무시, 같은 시점은 속도순, `재생력·자연회복`은 빈사 퇴장에 적용하지 않음 등.

## 구조(이미 있는 것)
- `AbilityModules.cs`: 도감 문장 정리 `Clean` → `AbilityPhrases.Rewrite` → `Fold` → 계속/사건 절마다 슬롯 포텐셜. `Sync`가 배틀 포켓몬에 붙인다(생성·특성 변경·무효화). `Rewrites` 사전에 특성별 표준 문장을 직접 줄 수 있다. `Runnable`은 `Dedicated`에 든 특성을 제외한다.
- `AbilityPhrases.cs`: 도감 변형 → 표준 문장, 새 계속 모듈(급소 무효·반드시 버팀·간접 대미지 무효·능력 하락 무효·설치물 무시·특성 관통·타입 추가·조건 우선도)과 판정 함수.
- 흡수 특성: `상대의 「X」 기술을 무효화한다.` + 트리거 `상대의 「X」 기술을 무효화했을 때, …`(`TriggerConditions` 모듈 「무효화」).
- 전용 코드 위치: `Mechanics.cs`(KnownAbilities·Block·StatusBlock·PowerFactor·Weather 등의 `Ability(...)` 호출), `AbilityRuntime.cs`(Enter·Leave·EndTurn·Power·Damage·BlocksCritical·Endures·Evasion·ChangeStage 계열).

## 부분 모듈(새로 할 일)
`AbilityModules.Dedicated`를 "전용 코드만 쓰는 특성"으로 바꾼다. 일부 문장만 모듈인 특성은 `Rewrites[이름]`에 모듈 문장만 넣고 `Dedicated`에서 빼서, 모듈 문장은 슬롯으로, 나머지는 전용 코드로 처리되게 한다. 같은 효과가 두 번 적용되지 않게(전용 코드에서 그 부분을 지운다) 반드시 확인한다.
