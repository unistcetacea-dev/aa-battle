## 2026-09-16 아쿠아링 상태변화 보강
- `아쿠아링`은 자신에게 붙는 `ConditionState` 상태변화로 저장하고, 턴 종료 회복 단계에서 최대 HP의 1/16을 내림해 회복한다. 상태창·전장 현황·상태 편집기·기술 대상 판정에서 같은 상태를 사용한다.
- 이미 아쿠아링이 있는 상태에서 다시 사용하면 실패하도록 처리했다. 일반 교대에서 상태가 새 포켓몬으로 복사되지 않는 기존 규칙도 유지한다.
- Pokémon Showdown 도감의 “매 턴 종료 시 최대 HP의 1/16 회복” 설명을 대조했으며, 관련 회귀 검사는 기술 검색/자기 대상/상태 표시/복제/턴 종료 회복/중복 사용 실패를 포함한다.

## 2026-10-12 가열·냉각·충전 / 악인·침수·송전
- 작업 브랜치: `task/state-charge-and-type-swap`. `ConditionState`에 6개 bool을 추가하고 복제·상태 표시·픽셀 상태 편집기·상태 도감에 연결했다. 타입 변경 3종은 `Mechanics.SetTypeSwap`과 편집기 체크에서 마지막에 적용한 하나만 유지한다.
- 기술 사용 시 원본 기술을 보존한 복사본으로 악/물/전기 단일 타입을 먼저 판정하고, 가열/냉각/충전은 판정 타입에 불꽃/얼음/전기가 포함될 때 각각 위력 2배를 적용한다. 복합타입에 여러 강화 상태가 대응하면 각각 곱하고 대응 상태를 모두 소모한다. 예약 기술도 사용 시점의 판정 타입·강화 위력을 보존한다.
- 기술을 실제로 내보낸 뒤 빗나감·방어·무효화·변화기 실패 여부와 무관하게 대응 강화 상태와 사용한 타입 변경 상태를 해제한다. 행동 불가 시 강화 상태는 소모하지 않고, 타입 변경 상태는 T종료에 해제한다. 기술 충전은 상태 부여/중복 실패만 처리하며 같은 기술로 새로 생긴 충전을 즉시 소모하지 않는다.

## 2026-10-12 침묵·망각·트집·회복봉인·사슬묶기·검은눈빛·조이기
- 작업 브랜치: `task/state-action-limits`. 7개 상태와 잔여 T, 봉인 기술명·직전 사용 기술명을 `ConditionState`에 추가하고 복제·라벨·픽셀 상태 편집기에 연결했다. 사슬묶기는 사용 이력이 없으면 부여할 수 없고 기본 4T, 회복봉인은 기본 5T, 조이기는 기본 4T다. 침묵·망각의 기간은 부여 API나 편집기에서 지정한다.
- `Mechanics.MoveBlock`을 `BeforeMove`와 `MoveCard`가 공유한다. 침묵은 소리 기술, 트집은 직전 기술의 반복, 사슬묶기는 봉인된 기술만 막는다. 사용 불가 버튼은 비활성화하고 상태명을 표시하며, 디더가 사유 글자를 덮지 않도록 기술 버튼 안에서만 렌더링을 보정했다.
- 망각은 DB 발버둥의 복사본을 사용하고 없으면 임시 기술을 만든다. 지시서의 노말·물리·위력50·필중·최대 HP 1/4 반동으로 맞추며 우선도와 대미지 미리보기도 대체 기술로 계산한다. 발버둥은 사용 이력을 바꾸지 않는다. 성공이 확정된 공격·변화기·예약 기술만 `LastMove`를 기록하고, 실패·빗나감·무효화된 행동은 이전 이력을 유지한다.
- 확인 답변에 따라 `StatusMove`의 새 자동 연결은 트집·사슬묶기·회복봉인·검은눈빛 4개뿐이다. 다른 상태는 부여 API·수동 편집으로 사용하며 포텐셜 효과 문장 자동 연결은 하지 않았다. 변화기 처리의 반환값으로 성공 여부를 전달해 실패한 변화기를 사용 이력에 기록하지 않는다.
- `Mechanics.Heal`은 회복봉인 중 0과 차단 로그를 반환한다. 먹다남은음식·아쿠아링·흡수 특성·회복 기술·회복 지령과 씨뿌리기 드레인의 회복을 차단한다. 드레인 대미지는 유지한다. 조이기는 슬립 대미지 단계에서 감소 전 최대 HP 1/8(최소 1)을 주며 매직가드를 따른다. 5개 기간 상태는 T종료마다 감소하고 만료 로그를 남긴다. 명중한 고속스핀은 조이기를 해제한다.
- `SwitchEffectRuntime.CanSwitch`에 교대 주체와 사유 반환을 추가했다. 검은눈빛·조이기는 통상교대 및 돌아와를 거부하되 유턴·포텐셜·강제교대는 막지 않는다. 기존 추적대원에 의한 비통상 교대 제한은 유지한다. 건 쪽이 떠나도 걸린 쪽의 상태는 유지한다.
- 후속 A: `Move.Copy()`는 MemberwiseClone 후 타입·태그 배열을 복제하며 `JudgedMove`가 이를 사용한다. 후속 B: `Mechanics.LeaveField`로 `Bench`와 엔진의 교대/퇴장 스냅샷 정리를 통합했다. 새 7개 상태·기술 이력, 이전 6개 상태, 아쿠아링·반동대기 등 장소 상태와 능력 보정을 해제한다.

## 2026-10-12 폭탄·요격·분노·마음의눈 / 회복·죽어내밀기 정리
- 작업 브랜치: `task/state-reactive`. `ConditionState`에 폭탄, 요격/분노 잔여 T, 마음의눈 부여 진영과 폭탄/마음의눈 부여 T를 추가했다. 복제·라벨·공용 LeaveField·픽셀 편집기에 연결했다. `Rules.Turn`을 복제·턴 종료에서 보존/증가시켜 이번 T 부여와 다음 T 만료를 구분한다.
- 접촉 공격으로 본체가 실제 대미지를 받으면 폭탄이 최대 HP 1/4(내림, 최소 1)의 추가 대미지를 주고 해제된다. 비접촉·대타는 반응하지 않으며 추가 대미지로 빈사가 될 수 있다. 지시서의 행동 후 해제도 적용해 보유자의 실제 기술 행동 뒤에는 폭탄이 풀린다. 새로 부여한 T종료에는 유지하고 다음 T종료에 만료된다.
- 요격은 기술 전체의 본체 실제 대미지 총합을 `Mechanics.AfterDamage`에 한 번 전달해 그 1/2(내림, 최소 1)을 공격자에게 반동으로 준다. 매직가드를 적용하고 반동 빈사를 허용한다. 기본 1T이며 지정한 잔여 T로도 부여할 수 있다. 분노는 본체 공격 피격마다 공통 ChangeStage로 공격 +1을 적용한다. 요격·분노는 T종료마다 감소한다.
- 마음의눈은 부여 진영의 상대 대상 기술만 명중 난수 판정 없이 필중으로 처리하며 실제 명중한 뒤 해제한다. 다른 진영·자기 대상 기술·방어 차단에는 소모되지 않는다. 부여한 T종료는 유지하고 다음 T종료에 만료된다. 일격필살은 마음의눈이 일치할 때만 필중하며 기존 맞춰라/필중 태그로는 필중시키지 않는다.
- DB에 분노·록온·마음의눈이 모두 존재했다. 분노는 사용자에게 4~5T(난수)를, 록온·마음의눈은 대상에게 부여 진영과 현재 T를 기록한다. 포텐셜 효과 문장 자동 연결은 하지 않았다.
- 정리 A: 재생력과 필드효과의 직접 HP 증가를 Mechanics.Heal로 통일해 회복봉인 차단 로그와 공통 회복 이벤트를 사용한다. T종료 회복 중복 금지의 대상 범위는 그대로다. 정리 B: ReplaceFainted가 퇴장 포켓몬에 LeaveField를 호출해 상태변화·사용 이력·능력 보정을 정리한다.
- 검증: `./desktop/verify.ps1 -Visual -OutputPath outputs/candidate` 통과(기계 회귀 212건, 기존 전투·편집기 검사). 폭탄 접촉/비접촉/대타/빈사, 요격 총합 1회/최소 1/매직가드, 분노 반복/기간, 마음의눈 진영/소모/만료/자기 대상 예외, 회복봉인 재생력/필드 회복, 실제 죽어내밀기 선택 경로를 검사했다. `reactive-conditions.png`에서 4개 상태와 부여 진영·잔여 T 입력을 확인했다.
- 범위 밖 발견/한계: 기존 엔진에 연속 타격 실행기와 일격필살 대미지 전용 경로가 없다. 총합 반동 API와 일격필살 필중 조건은 검사했지만 두 실행기는 새로 구현하지 않았다. 미래예지 계열의 별도 최후 예약 판정에는 이번 피격 반응을 연결하지 않았다. 기존 교대 스냅샷은 퇴장 특성 처리 전에 만들어져 재생력 등 변경이 보관본에 반영되지 않는 문제가 남아 있다. 바톤 인계·조임밴드/서펜타인·앵콜·추격 교대 캔슬 및 E~F 상태는 변경하지 않았다.

## 2026-10-12 남은 상태 / 잠듦 규칙
- 작업 브랜치: `task/state-final`. 도우미·헤롱헤롱·죽음의 카운트·동면·난동부리기·웅크리기와 잠자기 수면 이력을 ConditionState에 추가하고 복제·표시·편집·퇴장 정리에 연결했다. 모든 상태는 기술과 독립된 전투 상태다. 포텐셜·특성·필드·수동 판정 등 어떤 경로로 부여되어도 같은 엔진 규칙을 적용하며, 기술만의 추가 능력 상승/회복은 상태 부여와 분리한다. 자연어 효과 자동 연결은 이번에도 제외했다.
- 도우미 상태 자체가 다음 기술 위력 1.5배를 적용하고 사용 후/T종료에 소모된다. 예약 기술도 사용 시점에 강화 위력을 저장한다. 기술 도우미의 아군 대상은 현재 1대1의 활성 아군인 사용자 자신으로 처리하며 T종료에 해제한다. 사용자 결정으로 이 동작은 현행 유지한다. 웅크리기 상태 자체는 구르기·아이스볼만 2배로 만들고, 기술 웅크리기에만 방어·특방 +1을 붙였다.
- 헤롱헤롱은 행동 시 50% 실패한다. 진영 번호와 전장 내 상대 참조를 공용 퇴장 경로에 연결해 건 쪽의 통상교대·돌아와·효과 교대·죽어내밀기 퇴장에서 반대편 상태를 해제한다. 대상 퇴장에서도 해제한다. 성별 데이터가 없어 기술의 성별 조건은 사용자 지시대로 생략했다.
