# 특성 구현 상태와 보류 기준

특성은 포텐셜 데이터로 저장하지 않는다. 포켓몬의 `ability` 이름이 특성 도감의 독립 정의를 참조하며, 원문은 `ability-catalog.gz.b64`에 보존한다.

2026-10-13 사용자 결정으로 실행 방식을 바꾸었다: 특성 도감 문장을 포텐셜과 같은 트리거·효과 모듈로 읽어 같은 실행기로 돌린다(`AbilityModules`). 배틀용 복사본에만 슬롯 「특성」 포텐셜로 붙이고(특성 변경·무효화 때 다시 맞춘다), 로그는 〔특성명〕, 발동하면 「특성이 발동했을 때」 사건을 낸다. 사용 이력 키도 포텐셜과 따로다. 기준은 도감 문장 → 오레마스 문서 → 실기. 전용 코드로 처리하던 특성(`AbilityModules.Dedicated`)은 도감 문장 기준으로 다시 맞추면서 모듈로 옮긴다.

- 호출 기술의 구현 상태는 별개다. 일광욕은 광합성 추가행동을 선택하지만, 현재 광합성의 회복 문장은 기술 실행기가 읽지 못해 수동 판정이다. 괴짜(변신)는 폼 엔진, 트레이스(역할)는 기술 호출 연결이 필요해 이번에는 계속 수동으로 둔다.

- 2026-10-13 재정렬 결과, 기존 전용 코드 후보 63개 중 53개는 `AbilityModules`의 슬롯 「특성」 문장 모듈로 실행한다. 여기에는 날씨·지형 전개, 위협, 날씨 속도, 기술 위력, 흡수, 상태 면역, 방호, 능력 하락 방지, 특성 관통, 조건 우선도, 근성, 재생력, 가속이 포함된다. 발동은 공용 트리거 사건을 사용하고, 포켓몬 데이터에 포텐셜로 저장하지 않는다.
- 후속 모듈화로 남은 10개(`다운로드`, `단순`, `심술꾸러기`, `미러아머`, `날씨부정`, `에어록`, `틈새포착`, `부식`, `자연회복`, `화학변화가스`)도 이전했다. `AbilityModules.Dedicated`는 비어 있다. 능력치 비교 상태 트리거 + 등장 사건, 능력 변화량 추가·반전·반사, 날씨 효과 무효, 변화기술 방어 관통, 독/맹독 타입 면역 관통, 강제교대 포함 퇴장 치유, 상대 특성 무효 문장으로 실행한다. 세부 표준 문장과 판정 지점은 `PROJECT_HANDOFF.md`의 「전용 유지 특성 10개 모듈화」를 참고한다.
- 도감 문장에 맞춰 바뀐 동작: `타오르는불꽃`은 불꽃 기술을 흡수해 특공을 올리고, `수의베일`은 등장 시 아쿠아링 및 화상 면역, `마그마의무장`은 얼음/동면 면역 및 급소 방지, `방탄`은 탄/볼 무효 및 자폭/대폭발 반감, `부유`는 설치물을 무시한다. `옹골찬턱`은 턱 기술 강화와 가득 찬 HP에서 버팀, `마이페이스`는 도발 면역도 적용한다. `철주먹`·`메가런처`는 도감 수치인 1.5배를 쓴다. `재생력`은 공유 회복 경로를 통해 회복봉인의 영향을 받는다.
- 후속 결정: `자연회복`은 공용 치유 실행기의 HP 검사로 빈사 퇴장을 제외하며 강제교대도 치유한다. `짓궂은마음`의 악 타입 변화기 무효는 삭제되어 우선도 +1만 적용한다. `틈새포착`은 도감대로 변화기술의 방어 관통이며 대타·벽은 관통하지 않는다. `부식`은 지시서의 계속 문장대로 독/맹독 부여에서 타입 면역만 관통한다.
- 특성 무효화는 양쪽 문장 판정을 먼저 마치고 슬롯을 갱신한다. 제거된 특성 슬롯도 원래 문장으로 판정하므로 상호 무효화 순서에 영향받지 않는다. 무효화 기능을 가진 특성 자체는 면역, 일반 포텐셜의 무효화 효과는 다른 특성에 면역을 주지 않는다. 교대 시 등장 효과보다 먼저 갱신하며, 무효화된 채 퇴장한 특성 슬롯도 다시 복구한다.

## 사용자 확정 규칙 (2026-09-16)

- 전투 중 특성을 새로 얻어도 등장 특성은 즉시 발동하지 않는다. 다시 등장해야 한다.
- 특성 무효화가 끝나면 상시 특성만 즉시 재개한다. 등장 특성은 재등장 전까지 발동하지 않는다.
- `틀깨기` 계열은 상대 특성을 없애지 않고 해당 기술 판정의 방어 특성만 무시한다.
- 같은 시점 특성 처리는 속도순이다.
- 특성의 위력·능력·최종 대미지 배율은 포텐셜과 같은 계산 단계를 사용한다.
- HP 조건 방호는 연속기의 각 타격마다 다시 판정한다.
- 피격 교대 특성은 연속기를 모두 받은 뒤 교대한다.
- `자연회복`은 임의교대·강제교대·유턴·『돌아와！』에 적용하고 빈사 퇴장에는 적용하지 않는다.
- `재생력`은 임의교대·유턴·『돌아와！』에 적용하며 강제교대·빈사 퇴장에는 적용하지 않는다. **2026-10-13 사용자 본인의 의견으로 강제교대 발동을 원복한 결정**이며, 종전의 2026-09-16 규칙보다 우선한다. 일반 퇴장 트리거를 쓰고 회복봉인은 계속 적용한다.
- 폼 변경으로 최대 HP가 달라질 때 현재 HP 비율을 유지한다.
- 더블 배틀(다인전) 전용 효과와 싱글에서 대상 아군이 없는 효과, 배틀 밖 효과는 「효과 없음」 표준 문장으로 건너뛴다(2026-10-13 사용자 결정, 이전의 「다인전 전용은 수동」을 대체). 특성 전체면 실행할 문장이 없는 자동(도감 사유 「효과 없음(싱글)」), 한 문장뿐이면 그 문장만 건너뛰고 나머지는 실행한다.
- 『돌아와！』는 기존 포켓몬이 먼저 볼로 들어가 상대의 대상 지정 행동을 피한 뒤 턴 마지막 교대 시점에 새 포켓몬이 등장한다.

## 수동 사유 분류

특성 도감은 각 특성을 `자동` 또는 `수동`으로 표시하고, 수동 특성에는 아래 사유를 붙인다. 도감 검색은 이름·원문·분리된 트리거·효과·사유까지 포함한다.

| 사유 | 아직 필요한 하위 시스템 |
| --- | --- |
| 다인전 대상/범위 엔진 필요 | 인접, 아군 전체, 다수 대상의 선택·순서·대상 규칙 |
| PP·기술 이력/교체 엔진 필요 | PP, 마지막 사용 기술, 봉인·복사·교체 |
| 폼·종족 데이터 변경 엔진 필요 | 폼체인지, 변신, 종족치·타입의 지속/복원 |
| 특성 교체·무효화 상태 엔진 필요 | 특성 상실·교환·복사·무효화와 틀깨기 우선순위 |
| 선택/난수 규칙 확정 필요 | 임의 능력치·무작위 대상·확률 선택의 UI/난수 규칙 |
| 교대·파티 선택 엔진 필요 | 강제/임의 교대, 파티 대상, 교대 불가·추적 |
| 효과 실행기 미구현 | 위 범주에는 들지 않지만 전용 상태·기술·필드 규칙이 아직 없는 효과 |

수동 표기는 미구현을 숨기지 않기 위한 상태다. 효과 원문을 자동 실행 가능한 규칙으로 추정하지 않으며, 개별 특성은 필요한 하위 시스템이 추가된 후에만 `자동`으로 승격한다.
