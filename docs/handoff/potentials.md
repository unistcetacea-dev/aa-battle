# 포텐셜 (트리거·효과 모듈·ModuleCatalog) (PROJECT_HANDOFF.md에서 옮김)

## 포텐셜 연구

최신 도감 UI는 왼쪽의 **구조화 트리거 편집기**와 오른쪽의 **구조화 효과 편집기**로 구성한다. 트리거와 효과의 원문 검색·상세·원문 입력 버튼은 제거했다. `PotentialParts.cs`는 연구 및 구현 도감용 원문 구성요소를 계속 정규화하고 보존한다. 전각·공백·말미 구두점·단일 절 번호 표기를 통합하지만 확률·횟수·배율 등은 보존한다. 기본 구성요소는 조건 1,296개 / 효과 3,179개이며 `potential-parts.json`에 내보냈다. 구조 입력끼리는 서로의 값을 덮어쓰지 않으며 새 조합의 원문은 수집 원문으로 오인되지 않도록 비운다.

트리거 구조는 `TriggerStructures`에서 공통 정규화하고 각 배틀 사건 처리기가 이를 전달한다. `X`는 별도 발동 시점 없이 효과가 계속 적용되는 상시 조건이다. 필드/장소에 나왔을 때, 나오면 등의 일반 등장 표현은 `장소에 나올 때`로 정규화한다. `EntryTriggers.Enter`는 선발, 통상교대, 죽어내밀기 등에서 등장 트리거를 전달하고 `EntryReason.Forced`만 제외한다. `상대를 쓰러트렸을 때`는 `상대를 쓰러뜨렸을 때`로 통일하며, `DefeatTriggers.ByMove`는 효과를 가진 포켓몬이 사용한 기술의 직접 대미지로 상대 HP가 0이 된 경우에만 전달한다. 독·화상·날씨·설치물·반동·포텐셜 대미지는 이 트리거를 발생시키지 않는다.

추가 구조는 `PT에 참여하고 있을 때`, `T 종료 시`, `장소에 있는 한`, `아군과 임의교대할 때`, `상대의 공격을 받았을 때`다. 옵저버는 HP가 남은 대기 멤버일 때만 성립하고 장소에 나왔거나 빈사라면 꺼진다. `X`와 장소 유지 조건은 현재 장소의 살아 있는 포켓몬에게 상시 성립한다. 통상교대는 행동 대신 선택한 교대와 『돌아와！』이며, 임의교대는 통상교대·유턴 계열·포텐셜 교대를 포함하고 강제교대만 제외한다. 피격은 기술 전체가 끝난 뒤 본체가 받은 직접 대미지가 있을 때 한 번만 전달하며 회피·무효·대타와 빈사 상태는 제외한다.

다음 구조는 `장소를 떠날 때`, 등장 방법 지정, `적진에 「타입」 포켓몬이 있을 때`, `트레이너가 「자질:등급」 이상일 때`, `상대의 공격을 받았거나 무효화했을 때`다. 장소 퇴장은 강제교대를 제외하고 빈사로 퇴장할 때도 성립한다. 등장 방법은 선발, 죽어내밀기, 임의교대 및 선발·죽어내밀기 공통으로 나누며 강제교대는 제외한다. 적진 타입은 상대의 현재 원래·추가·변경 타입을 대상으로 한다. 자질 등급은 부호만 무시한 같은 알파벳 등급대에서 성립하므로 A-/A/A+는 A 조건에 맞지만 AA는 맞지 않는다. 피격·무효화 구조의 무효화는 공격 기술이 타입·특성·도구·방호 포텐셜로 막힌 경우이며 방어·판별, 회피, 빗나감, 대타는 제외한다.

구조화 트리거와 효과 편집기는 선택한 구조가 사용하는 입력만 표시한다. 적진 타입 조건에서는 타입만, 자질 조건에서는 자질과 등급만, 수치 배율 효과에서는 배율만, 랭크 변화에서는 변화 랭크만 편집한다.

이번 구조는 `「여기다！」일 때`, `자신이 지령을 받았을 때`, `아군이 지령을 받았을 때`, `『계약의 특권』이 부여되어 있을 때`, `상대의 데이터를 해석했을 때`다. 여기다는 시작 편성 6체 이상=생존 3체 이하, 4~5체=2체 이하, 3체 이하=최후의 1체에서 성립하며 적진의 살아 있는 『에이스』·『탐사대장』도 성립시킨다. 한번 성립하면 부활 후에도 유지한다. `자신`은 현재 대상 포켓몬, `아군`은 대기를 포함한 살아 있는 파티 전체의 사건을 감시하는 범위로 모든 후속 구조에서도 구분한다. 지령 사용 시 두 범위의 트리거를 각각 전달한다.

선행 발동 방식은 구조화 트리거 편집기에서 지정한다. 현재 포켓몬이 보유한 사용 가능한 선행입력 포텐셜은 지시창에 복수 선택 항목으로 나오며 1/시 사용 이력을 보존한다. 효과가 `할 수 있다`이면 발동 여부를 묻고 거절한 항목은 소비하지 않는다. 의미가 불명확한 `턴 중 선언 시`는 정규화 단계에서 제거한다.

『특권』 고정 템플릿은 사용자 제공 효과의 18타입 『익스펜션』과 『계약의 특권』, 『주인의 특권』, 『왕자의 특권』이다. 복합 효과는 CRLF로 나눈 독립 효과 목록으로 저장하고 구조화 효과 편집기의 `효과 추가 +`로 기존 효과를 보존하며 새 효과를 붙인다. 계약은 타입 선택값과 일치하는 상대 기술 대미지를 반감한다. 주인·왕자는 체력 종족치에 계산 설정의 `종족치 ‘조금’` 값을 더하며 기본값은 10이다. 왕자는 추가로 상대로부터의 상태이상을 무효화한다. 고정 템플릿 효과는 기본 보호 효과에 포함한다.

추가 트리거 구조는 `배틀 시작 시`, `상대가 장소에 나왔을 때`, 기술 사용 전체·공격·변화·타입·특정 기술, `공격이 성공했을 때`, `대미지를 받았을 때`, `XX가 부여되어 있을 때`다. 상대 등장은 강제교대를 포함한다. 기술 사용은 행동 가능 판정 뒤 실제 기술 처리 직전에 변화기에도 전달한다. 공격 성공은 명중한 공격기술 한 번의 처리가 끝난 뒤 전달하며 변화기는 제외한다. 대미지 수신은 기술·자해·날씨·상태이상·설치물·포텐셜 등 실제 HP 감소를 하나의 사건으로 통합하고 빈사 시에도 전달한다. 이름별 부여 조건은 계약 전용 분기를 쓰지 않고 해당 포텐셜 보유 여부로 판정한다.

배틀의 `상대 해석` 버튼은 상대별 최초 1회만 도감을 사용한다. 해석 창은 아스키아트, 레벨, 타입, 특성, 종족치, 기술, 일반 포텐셜을 공개하고 현재 체력·도구·전용 포텐셜은 숨긴다. 최초 공개 직후 `상대의 데이터를 해석했을 때` 트리거를 전달한다.

턴 종료는 속도순으로 슬립 대미지, 드레인, 회복, 상태 해제를 처리한 뒤 `T 종료 시`를 전달한다. 같은 타이밍의 포켓몬 트리거는 속도가 빠른 쪽부터 처리한다. 자연어 효과 실행기는 아직 준비 중이므로 현재 트리거 처리는 성립한 포텐셜과 효과 판정 대기를 로그·전장 현황에 전달하는 단계다.

2026-09-15 현재 정규화 결과는 조건 1,234개 / 효과 3,159개다. 이 중 52개를 구현 도감에서 제외해 구현 대상은 3,107개다. 연구 원문 4,151개와 출처는 보존한다. 역할·범용·선·회피/내성/격·부수·지령·특권 템플릿에서 나온 효과는 `protectedTemplate=true`로 자동 보호하며 도감에 `[기본 보호]`로 표시한다. 보호 효과는 중복 정리나 구현 분류 과정에서 삭제·치환하지 않는다.

효과 정리는 연구 원문을 삭제하지 않고 `excludedFromImplementation`과 제외 사유를 기록한다. 독립 주석, 편성/공유 규칙, 배틀 외 경험치/상금 획득 규칙만 구현 효과 도감에서 숨기며 `protectedTemplate` 항목이 항상 우선한다.

상단 `효과 구현 방식` 버튼과 같은 이름의 탭은 `EffectImplementationDex`를 연다. 제외 후 3,106개 효과를 자동 구현/일부 자동 구현/구현 규칙 준비/기준 질문 필요/미구현으로 표시하고, 선택한 효과의 해석·현재 코드 처리·출처를 보여 준다. 현재 포켓몬의 자연어 포텐셜 효과는 자동 실행되지 않으며, 트레이너 4식·지령만 `Engine.Resolve`/`Engine.ApplyOrder`에서 실행된다.

`PotentialProbability`는 드물게=10%, 저확률=20%, 중확률=50%로 정의한다. 한 포켓몬에서 같은 발동 시점에 성립한 중확률 후보가 2개 이상이고 독립 판정이 전부 실패하면 그중 하나를 무작위로 강제 발동한다. 원래 판정에서 여러 개가 성공했다면 모두 발동한다. 고확률은 지원하지 않으며 해당 표현은 원문을 보존한 채 구현 도감에서 제외한다. 현재 구현 대상에는 고확률 표현이 없다.

`EffectStructures`는 기본 보호 효과를 건드리지 않고 단순 배율 문장, 단순 최대 HP 분수 문장, 단순 능력 랭크 변화 문장을 구조화한다. 포텐셜 도감에서는 효과 원문을 찾지 않고 구조, 대상, 동작, 배율/N/랭크를 직접 정한다. 현재 구조는 능력 랭크 변화, 종족치 변경, 수치 배율, 최대 HP의 1/N이며 구조를 고르면 가능한 대상과 동작만 표시한다. `FractionalHpRule`은 최대 HP/N의 소수점을 버리고 최소 1로 처리한다. 대미지는 기본적으로 빈사가 가능하고, 빈사 불가로 지정한 효과만 HP 1에서 멈춘다. 랭크 변화는 오른다/내린다=±1, 크게 오른다/내린다=±2, 매우 크게 오른다/내린다=±3으로 정규화한다. 쭉 오른다/급격히 오른다는 원문만 보존하고 구현 목록에서 제외한다. 급소 확률, 트레이너 지시처럼 포켓몬 전투 능력치가 아닌 대상은 이 구조에 합치지 않는다. 복합 효과와 기본 보호 효과의 원문은 유지한다.

능력 선택 표현은 두 구조로 구분한다. `임의의 능력`은 사용자가 공격·방어·특공·특방·속도·명중·회피·C 중 하나를 선택한다. `랜덤한 능력치`는 공격·방어·특공·특방·속도 중 하나를 같은 확률로 자동 선택한다. `Fighter.CriticalStage`가 C 랭크를 저장하고 전장 전체 현황에 표시한다. 자연어 포텐셜 실행기와 급소 계산 연결은 아직 준비 단계다.

`가장 높은/낮은 능력`은 공격·방어·특공·특방·속도의 `Engine.Effective` 값을 비교한다. 현재 랭크, 직접 강화·약화 배율, 상태와 장소 보정이 반영되며 동률 후보는 같은 확률로 자동 선택한다. `가장 높은/낮은 종족치` 문장은 이 규칙에 합치지 않는다.

`가장 높은/낮은 종족치`는 포켓몬의 원래 공격·방어·특공·특방·속도 종족값을 비교하고, 동률 후보 중 하나를 같은 확률로 자동 선택한다. 랭크와 배율은 반영하지 않는다.

`SpeciesStatRanks`는 종족치 1·2랭크 상승 범위를 계산한다. 기존의 `-`, 무표기, `+`를 유지해 지정한 수만큼 문자 등급을 이동한다. 예를 들어 B-=90은 1랭크에서 A-=110, 2랭크에서 AA-=140이 된다. B+=105~109는 1랭크에서 A+=135~139, 2랭크에서 AA+=165~169가 된다. S는 200~999로 제한한다. 구조화 편집기에서 현재 포켓몬과 대상 종족치를 읽어 이 범위 안의 값만 입력받는다.

지정 종족치 등급 구조는 E-부터 AAA+와 S를 선택하고 해당 등급 범위 안에서 실제 수치를 고른다. `지정 등급까지 상승`은 현재 값이 설정값보다 낮을 때만 올리고, `지정 등급까지 하락`은 현재 값이 설정값보다 높을 때만 내린다. `지정 등급으로 변경`은 현재 값과 관계없이 설정값으로 바꾼다. 복수 능력과 상대 능력도 대상으로 선택할 수 있다.

`다른 종족치 복사`는 대상과 복사 원본 능력을 따로 선택한다. `같게 한다`와 `동랭크까지 올린다`를 모두 현재 대소 관계 확인 없이 원본 능력의 실제 종족치 숫자를 대상에 복사하는 규칙으로 처리한다.

도감의 표·상세·검색 표시에는 Pokemon BW 글꼴을 사용한다. 해당 OTF는 기본 GDI 텍스트 렌더러에서 글자가 깨지므로 GDI+로 그린다. 검색 입력 중에는 한글 IME를 지원하는 기본 입력기를 사용하고, 포커스를 벗어나면 도트 글꼴로 표시한다. 이전의 이름·종류·출처 열은 도감에서 제거했으며 원본 자료에는 보존한다.

## 트리거 모듈화 계획 (1~3단계 완료, 위 항목 참고)
- 배경: 수집 트리거는 서로 다른 문장 1040개(등장 2816회). 지금은 고정 라벨 문자열(`TriggerStructures`)과 흩어진 정규식(`RuntimeTriggers`·`AnsweredTriggers`·`EntryTriggers`)으로 처리하고, 편집기 「구조」는 90여 개 완성 문장 + `|` 구분 값 입력이다.
- 가족별 등장 횟수: 적진·아군 구성 365, 상태(있음/됨) 255, 등장 230, 특성·소지품 188, 피격 182, 트레이너·지령 155, 날씨·지형 154, 교대·퇴장 128, 명중·쓰러뜨림 126, 턴 타이밍 112, 체력 97, 기술 사용 79, 랭크 45, 해석 38, 기타 614.
- 방식(효과 모듈과 같게): `TriggerModules`에 표준 문장 · 모듈(사건 「~했을 때·됐을 때」 / 상태 「~일 때·있는 한」) × 주체(자신/상대/아군/서로) × 값(`MoveCondition`·상태 이름·체력 비율·날씨·타입·등급)을 두고, 수집 변형은 `Normalize`, 판정은 `Classify`. 엔진 사건 지점은 라벨 문자열 대신 모듈+값으로 발동, 상태 모듈은 `StateHolds`에 연결. 편집기 트리거 구조를 모듈 → 주체 → 값 선택식으로 바꾸고 「그리고/또는」, 「X한 T 종료시」(사건+타이밍) 결합 지원. 실행되는 트리거는 도감에서 구현됨으로 표시.
- 순서: 1단계 등장·교대·턴 타이밍·피격·명중·기술 사용 → 2단계 상태·체력·날씨·랭크 → 3단계 구성·트레이너·특성·소지품.
- 사용자에게 확인할 것: ① 「기술을 내보낼 때」(직전)와 「내보냈을 때」(직후)를 다른 타이밍으로 둘지 ② 「공격 명중 시」와 「공격이 성공했을 때」를 같게 볼지(타이밍 규칙 6: 성공은 쓰러뜨려도 그 시점) ③ 「「X」을 쓰러뜨렸을 때」·「「캐롤」이 트레이너일 때」 같은 고유 이름 조건을 모듈 값으로 받을지, 판정 대기로 둘지.

- 도만 『아름다운 육식수』 「상대의 「저주」대미지가 무효화되지 않는다」 = 자신이 건 저주 대미지는 매직가드·「공격 이외 대미지 무시/무효」로도 막히지 않는다. **구현**.
- 『황금』 「트레이너가 「유키나리」일 때, 포텐셜을 다시 받을 확률이 오른다」 = 유대의 재사용 확률 상승. 지금은 크게 신경 쓰지 않아도 됨 — 구현한다면 유대 재사용 확률을 한 단계 올린다(저확률→중확률). 「유대와 황금의 대상」 = 빼앗아 쓴 전용도 유대 이력에 들어간다는 뜻.

- 우선도 모듈은 하나다. `effect.priority.올린다`가 기술 조건 빈칸(비우면 모든 기술)을 갖고, 선택값 「올린다/-0.5」로 조건 우선도 -0.5(`ability.priority.lag`)를 묶는다. 옛 `ability.priority.condition`은 없어졌다. 표준 문장은 「자신의 「조건」 기술 우선도를 N 올린다」이고 옛 「…기술의 우선도를 +N한다」는 `AbilityPhrases.Normalize`·`PhraseRules`가 바꾼다(실행기 `AbilityPhrases.PriorityBonus`는 옛 꼴도 읽는다). 도감 효과 문장 정규화 덤프 전후 차이는 이 조건 우선도 문장 8줄뿐이다. 조건 없는 -0.5(`effect.priority.lag`, 느림보꼬리)는 별도 모듈로 남아 있다.
- 검사 수 점검: 검사가 빠지는 것은 없다. 요약의 「전체」는 `Explicit` 연구 도구 3개(`JudgeSheet`·`DumpCatalog`·`Probe`, `ChaldeaJudgeTool.cs`)를 뺀 수이고 실제 목록(`--list-tests`, trx)은 그보다 3개 많다. O에서 케이스를 늘렸는데 수가 거의 안 늘어난 것은 모듈을 합치면서 모듈별 검사(`ModuleDefault_`·`CoreSchema_`, 모듈당 하나씩)가 22개 줄고 `OChoice_` 33개가 늘었기 때문이다. `TableRow_` 이름 9쌍이 겹쳐 있던 것은 번호를 붙여 구분했다.

### 사용자 결정 (P 후속, 2026-10-14)
- 조건 없는 「우선도 −0.5」 모듈(`effect.priority.lag`)은 합친 우선도 모듈의 「−0.5」 선택값과 **하나로 합친다**.
- 『아름다운 육식수』의 저주 관통은 **저주를 건 보유자가 장소에 있는 동안만** 유지된다. 보유자가 교대로 나가거나 빈사가 되면 그 저주의 관통이 **사라지고**(저주 자체는 남아 평소처럼 면역에 막힘), 같은 보유자에게 저주를 **다시 받을 때** 관통이 다시 붙는다.
- P 후속 구현: 조건 없는 `effect.priority.lag`(느림보꼬리)는 합친 우선도 모듈의 「-0.5」 선택값이 되었다(정규화 덤프 전후 차이 없음). 저주 관통은 건 보유자가 장소에 있고 빈사가 아닌 동안만 유지된다: 보유자가 퇴장하면(`LeaveField`) 또는 판정 때 빈사·퇴장이면 `CurseSource`를 비운다(저주는 남고 매직가드에 막힌다). 이미 저주 상태면 다시 걸리지 않으므로 관통은 저주가 풀린 뒤 다시 걸릴 때 붙는다.

- 탐사대원·야생 포켓몬의 「임의의 능력」: `RoleEntryRuntime`의 이름별 무작위 상승을 없애고 역할 문장이 표준 경로(`RunRank` 임의, `Rules.ChooseStat`)로 한 번만 처리한다. 선택기가 없거나 취소하면 판정 대기(상승 없음).
- 선발 등장(MainForm.LoadTeams)은 EffectScope 안에서 EntryTriggers.Enter를 돌려 「장소에 나올 때」 포텐셜(탐사대원 선택 창 포함)을 배틀 준비 직후 처리하고 EntryTriggered를 세워 첫 Resolve에서 다시 일어나지 않게 한다.
- 죽어내밀기(ReplaceFainted)도 LoadTeams처럼 EffectScope 안에서 EntryTriggers.Enter(..., immediate: true)로 선택 직후 바로 처리한다(미룸 없음, EntryTriggered로 다음 Resolve 중복 방지). 엔진 내부 호출은 기존대로 인터벌 등장을 다음 T 처음으로 미룬다.
