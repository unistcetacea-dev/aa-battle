# 지시서: 전용 유지 특성 10개를 모듈로 옮기기

작성: Claude (2026-10-13) · 구현: ChatGPT(Codex) · 브랜치: `task/ability-dedicated-modules`
**선행 작업**: `2026-10-13-ability-realign-fix.md`가 병합된 뒤에 시작한다(자연회복이 거기서 만드는 「강제교대를 포함한 퇴장」 트리거를 쓴다).

먼저 `AGENTS.md`, `PROJECT_HANDOFF.md`의 특성 항목들, 앞의 두 지시서를 읽는다.

## 목표 (사용자 결정)
`AbilityModules.Dedicated`에 남은 10개를 모두 도감 문장 기준 모듈로 옮기고 `Dedicated`를 비운다. 특성 이름 판정(`Ability(x,"이름")`, `Has(x,"이름")`)과 전용 처리 코드는 지운다. 각 기능은 표준 문장 + 판정 지점으로 된 **새 모듈**로 만들고 `AbilityPhrases`의 `Normalize/Classify`에 연결한다(포텐셜에서도 쓸 수 있게). 기준은 도감 문장 → 오레마스 문서 → 실기.

## 특성별 설계
도감 문장은 `AbilityCatalog.Find(이름).effect`로 다시 확인한다. 표준 문장은 예시이며, 기존 모듈 문장 형식에 맞게 다듬어도 된다(바꾸면 보고).

| 특성 | 도감 | 새 모듈 / 처리 |
|---|---|---|
| 다운로드 | 등장 시 상대의 「방어>특방」이면 특공, 아니면 공격이 오른다 | 새 트리거 상태 모듈(능력치 비교): `상대의 「방어」가 「특방」보다 높을 때` / `… 이하일 때`. 등장 사건 + 비교 상태(AND, 확정 48)로 포텐셜 두 개 |
| 단순 | 자신의 능력이 변화했을 때 같은 능력을 ±1(변화량 ±1 추가) | 계속 모듈 `자신의 능력 변화량을 1 늘린다.` — `Mechanics.ChangeStage`의 해당 처리를 모듈 판정으로 |
| 심술꾸러기 | 자신에 대한 「능력변화」 효과를 반전한다 | 계속 모듈 `자신에 대한 능력 변화를 반대로 한다.` — ChangeStage |
| 미러아머 | 상대의 능력 감소 효과를 반사한다 | 계속 모듈 `상대에 의한 능력 하락을 상대에게 되돌린다.` — ChangeStage(반사된 하락은 다시 반사하지 않는다) |
| 날씨부정·에어록 | 날씨의 효과를 무효화한다 | 계속 모듈 `날씨의 효과를 무효화한다.` — `Mechanics.Weather`의 이름 판정을 모듈로(장소에 있는 쪽 누구든) |
| 틈새포착 | 자신의 변화기술이 상대의 「방어」 등의 기술을 관통한다 | **동작 변경**: 지금 구현(대타·벽 관통, 실기)이 아니라 도감대로 「변화기술의 방어 관통」. 기존 방호 관통 모듈 문장(`자신의 「변화」 기술이 상대의 「방어」 기술을 관통한다.` 등 가까운 형식)이 있으면 그것으로, 없으면 새로. 대타·벽 관통 처리는 지운다 |
| 부식 | 자신의 「추가효과：독/맹독」이 「독」「강철」 타입에 의해 무효화되지 않는다 | 계속 모듈 `자신이 거는 「독」「맹독」은 타입 면역을 관통한다.` — 상태이상 면역 판정에서 |
| 자연회복 | 필드를 떠날 때, 자신의 「상태이상」을 치유한다 | 선행 작업의 강제교대 포함 퇴장 트리거 + 상태이상 치유 모듈. 빈사 퇴장 제외 확인 |
| 화학변화가스 | 상대의 〔특성〕을 무효화한다 | 계속 모듈 `상대의 〔특성〕을 무효화한다.` — `AbilityRuntime.RefreshSuppression`의 이름 판정(`Gas`)을 모듈 판정으로. 2026-09-16 규칙 유지(무효화가 끝나면 상시 효과만 재개, 등장 효과는 재등장까지 없음, 이 특성 자신은 무효화되지 않음) |

주의: 화학변화가스 판정은 특성 슬롯 포텐셜을 읽는데, 무효화된 쪽은 슬롯이 빠진다(`AbilityModules.Sync`). 서로 화학변화가스인 경우·무효화 해제 순서가 꼬이지 않게 한다.
