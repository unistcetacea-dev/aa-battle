# 지시서: 트리거 「기본 조건」 묶음 해체

작성: Claude · 구현: Claude Sonnet(서브에이전트) · 기준 커밋: `2cc2138` · 브랜치: `task/trigger-basic-split`

먼저 `AGENTS.md`, `PROJECT_HANDOFF.md`의 모듈 목록(ModuleCatalog) 절, 지시서 B(`2026-10-14-module-schema-editor.md`)를 읽는다.

## 문제
트리거 편집기의 분류 「기본 조건」에 고정 문장 모듈 49개가 섞여 있다(`ModuleCatalog.Triggers.cs`의 `TL(...)` 도우미가 분류를 「기본 조건」으로 고정). 빈칸이 없는 고정 문장이고, 같은 꼴의 문장(주체·비교·대상만 다름)이 따로따로 등록되어 있다.

## 사용자 결정
1. 「기본 조건」에 있는 모듈을 모두 꺼내 알맞은 분류로 나눈다. 그 뒤 「기본 조건」 분류와 `TL` 도우미를 지운다.
2. 「조건 A 그리고 조건 B」는 트리거 줄을 따로 두 줄 쓰는 AND로 읽는다(지금 동작 유지, 확인만).

## 할 일
1. **분류 배정**: `TL` 호출 49개(`ModuleCatalog.Triggers.cs`·`.Triggers.Conditions.cs`·`.Triggers.States.cs`)를 기존 분류(등장·교대 / 턴·행동 / 기술·대미지 / 체력·상태 / 능력 / 소지품·특성 / 파티·트레이너 / 날씨·장소 등 현재 쓰이는 이름)로 옮긴다. 맞는 분류가 없으면 새 분류를 만든다(예: 「상시·배틀」, 「데이터 해석」). 분류는 편집기 첫 단계 목록이므로 너무 잘게 쪼개지 않는다(분류 하나에 모듈 2개 이상이 되게).
2. **같은 꼴 합치기**: 한 단어만 다른 형제 문장은 빈칸 하나짜리 모듈로 합친다. 예:
   - 지령: 자신/아군 → `{주체}가 지령을 받았을 때`처럼(실제 표준 문장 그대로).
   - 행동 선택 「서로 {변화기술/공격기/필중 기술}을 선택했을 때」, 공격하지 않는 행동 선택 자신/상대, 먼저 행동할 때·했을 때 자신/상대.
   - 방어로 공격/기술 무효화, 해석 상태 3종, 빈사 수 많을/같을/적을, 속도 높음/낮음, 공중 자신/서로, 상대 교대/임의교대, 쓰러뜨림 일반/아인종.
   - **표준 문장은 글자 그대로 유지한다**(`TriggerModules`가 읽는 문장, 새 형식 금지). 조사가 달라지는 경우(「을/를」 등)는 선택지에 조사까지 넣거나 그대로 따로 둔다.
   - `TriggerSpec` 필드로 왕복이 안 되는 경우는 선택지 목록에서 문장을 만드는 공용 도우미(선택 빈칸 → 문장, `TriggerModules.Parse(문장).Module == 모듈` 확인, `TryRead`는 선택지마다 대조)를 하나 만든다. 이름별 분기 금지.
3. 합칠 수 없는 고정 문장(상시·장소에 있는 한·여기다·배틀 시작 등)은 빈칸 없는 모듈로 두되 알맞은 분류에 넣는다.
4. 모듈 id는 바꿔도 되지만, 편집기에 이미 저장된 문장이 다시 열릴 때 `TryRead`로 같은 모듈·같은 값이 채워져야 한다(문장 기준이라 id 변경은 저장 데이터에 영향 없음 — 확인만).
